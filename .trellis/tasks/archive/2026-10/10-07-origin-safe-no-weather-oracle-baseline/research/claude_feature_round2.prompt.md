1. A pooled bridge with only m valid values may be entirely historical when every future value is missing, yet its name implies an oracle bridge. Even when both halves pass separately, varying valid counts changes relative weights. Prefer reuse of baseline R_v=roll{m}_mean_asofH (existing minimum-count rule) and bridge B_v=(R_v+F_v)/2 with BOTH nonmissing. This fixed weighting is exact on complete data and refuses historical-only fallback. Do you accept? If not, give a concrete counterexample and a better bounded contract.

2. For NEW future summaries require ALL m future source values finite; compound monthly summaries require all paired months. Raw oracle keeps whatever cells exist; aggregated features become NaN on incomplete windows, never drop the row. Historical roll{m} retains its existing baseline min-periods/missingness. I favor deferring this manual GS term; retain all existing GS baseline inputs. If retained, its claim must be strictly 'negative precipitation anomaly in latest completed season and future window', with units/support limitations, no crop-failure inference.
