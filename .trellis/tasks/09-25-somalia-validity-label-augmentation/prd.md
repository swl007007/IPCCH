# Somalia validity-period label augmentation

## Goal

Plan reconstruction of Somalia labels using current-period IPC validity dates while retaining original raw covariates; compare original and augmented D direct/residual/selected with persistence and all-crisis.

Version0.3, 2026-09-25. Status: G1-G3 resolved; final technical review accepted with implement.md (see Final acceptance). New planning task creation is approved. Implementation, feature regeneration, fitting and audited start authorized 2026-09-25 (see Final acceptance). Do not alter the separate q3-optimization task or its artifacts.

## Confirmed intent and baseline

- User priority: overall performance after adding labels is the main result; performance restricted to original/common labeled samples is secondary. Approved comparison: both original-label-trained and augmented-label-trained D predict the same expanded evaluation cohort, with coverage reported; each branch uses its own allowed training labels for fitting, selection and calibration.
- Compare original versus augmented D, each with direct, residual and training-validation-selected views, against persistence and all-crisis. A-C reruns are not requested.
- Retain original raw covariate sources and original label values. The user approved an augmentation-only policy: attach source validity metadata only where the report/period correspondence is defensible; do not replace old values with newer API values. Expand within that matched validity rather than unrestricted forward filling. Unresolved mappings/conflicts remain explicit diagnostics, not guessed augmentation.
- Current reuse baseline is q3-first v2 (`reports/somalia_oracle/v2_q3/summary.md`): train2022-24/test2025 and train2023-25/test2026; H0 optimized, H3/6/12 ancillary; strict q3 RMSE selection, AUC numerical tie-break; D residual and same-bundle direct fallback; none/shift/isotonic calibration; q3>=.2 crisis decision. Carry these forward as the working baseline unless the new label semantics require an explicit change.
- In that report, H0 D-selected final R2 is .138 for2025 and .062 for2026; 2026 D-direct is .213 and share persistence .220. These are previously reported outcomes, not a new audit or a performance promise for augmentation.

- R6. Reuse the q3-first pipeline and existing covariate feature definitions. Use one fixed complete monthly deep-feature source and neighbor definition for both label branches; recover added-month scope features with the existing full-month upstream logic and check parity on old keys. Rebuild only label-derived history under R8/R9. Do not copy another month's X, independently redefine spatial/static features by label branch, or drop added labels merely because current fs files contain only old labeled months. Target columns in a target-corrected feature artifact are not authority to revise the raw labels preserved by R7.
- R7. Source-value authority approved 2026-09-25 ("采用"): preserve raw overall_phase and phase-percentage values; borrow only validity metadata linked to the original record by defensible report/period evidence. Keep the original normalization policy for model targets. Newer API values do not overwrite originals. Unmatched records and unresolved value/version/period conflicts remain in the diagnostic ledger and original branch; no window is invented for them. Merely matching a nearby geometry, month or similar label does not establish report identity. Reduced augmentation coverage is acceptable where correspondence cannot be established; report it explicitly.
- R8. Historical information-set rule approved 2026-09-25 ("采用"): count distinct original reports, not expanded month copies, when constructing history. Exclude the target's own source report and all its copies from that target's historical predictors, q3 residual baseline and share/phase persistence. Apply the same rule to original-label and augmented-label D and their baselines, at every feature row's own origin. This includes rich-history slots/windows and any preassembled categorical phase-history fields; source identity is distinct from numerical label equality. Preserve original report timing so an expanded copy does not become a new observation or reset history age. This is prediction excluding the target assessment, not a carry-forward evaluation of a report already known at the origin. R9 adds the fitting/scoring isolation rule.
- R9. Report isolation approved 2026-09-25 ("采用"): for each outer evaluation or inner validation scoring fold, remove every copy of its scoring reports from that fold's model-fitting and calibration-fitting label pools, retaining chronological cutoffs and the scoring keys. Apply the same protocol to original-label and augmented-label D. Keep report exclusions and lost fitting support in the ledger; insufficient support is explicit, not repaired with scoring reports. OOF predictions used to fit a calibration mapping must themselves respect the report exclusions of the scoring comparison they serve. R8's historical-input rule remains in force, so exclusion from Y cannot be bypassed by using the scoring assessment through a historical feature. Exact source-group identity and context-dependent feature construction will be specified before implementation.
- R10. Availability rule approved 2026-09-25 ("采用"): under the existing ideal-availability assumption, an original raw label becomes available at the end of its original observation month. Every expanded copy retains that source availability date. Validity dates identify months described by the assessment, not earlier publication or repeated releases. Model fitting, history and calibration eligibility must satisfy both their temporal row cutoff and the original report's availability cutoff, as well as R8/R9 report exclusions. Retrospective scoring truth may describe months earlier than source availability, but must not enter inputs or fitting before it is available. Preserve target_month, original_observation_month, source_available_at, valid_from and valid_to as separate provenance. API created/modified dates are not substituted for verified publication dates; this remains an explicit ideal assumption, not reconstructed operational availability.
- R11. Duration weighting explicitly directed 2026-09-25: reject report-balanced training/calibration. Copy the existing label into previously unlabeled months within its verified validity window, and treat each added area-month as a training row. Longer valid periods intentionally gain greater total fitting influence. Retain the established per-row model time-decay weighting and per-row calibration fitting; do not divide by report length, replicate count, or number of areas. Do not oversample beyond one canonical row per area/month or overwrite an existing label. Primary validation/evaluation remains per-area-month, not report-balanced. R8/R9/R10 continue to govern history deduplication, report isolation and availability: added fitting weight does not mean a copied month is a new independent report. Report added counts and summed weights to make the intended duration effect explicit.
- R12. Overlap priority approved 2026-09-25 ("采用"): an existing raw label always takes precedence and is not overwritten. For a previously unlabeled area-month covered by multiple defensibly linked reports, use the report with the latest original observation month. If equally dated candidates disagree on label values, leave the cell unfilled and record the conflict; never average or select by model performance. Preserve the chosen report's availability date under R10 even for retrospective target truth. This precedence does not make an unverified spatial/report match valid.
- R13. Comparison protocol approved 2026-09-25 ("采用"): refit and reselect both original-label and augmented-label D with identical candidate/calibration budgets and the same report-isolation/availability protocol. Each branch uses only its own permitted training-period labels for model fitting, inner selection and calibration. Both predict the same expanded outer evaluation truth. Retain direct/residual/selected views in each branch; saved v2 results are historical context rather than an unchanged comparator under the new report exclusions. No augmented training/calibration labels are supplied to the original branch.
- R14. Grill G1 approved 2026-09-25 ("采用"): use the latest three eligible distinct original-report observation months as chronological selection/calibration rounds, requiring at least two supported rounds. Expanded copies do not count as additional reporting rounds. Within a round, retain all eligible monthly rows of the branch with their normal row weights, preserving the intended greater influence of longer validity. Earlier calibration rounds still obey source availability and scoring-report exclusions. Record original-round dates separately from target-month counts; three copied months cannot satisfy a multiple-round support requirement.
- R15. Grill G2 approved 2026-09-25 ("采用"): fill only area-months where overall_phase and all five phase percentages are missing. No component-wise filling, mixing sources or relabeling zeros as missing. Retain the original/model-normalized representations separately.

## Acceptance Criteria

- Exact input snapshots, stable area mapping and source report/window identity are recorded, with conflict and unmatched counts.
- Expanded labels obey the agreed inclusive/exclusive boundaries, overlap priority, value authority and coverage cap, and original labels remain traceable.
- Original label values remain intact; each added row traces to an original label and a verified validity window. Unresolved rows are not silently replaced, paired or extended.
- Main expanded-cohort and secondary restricted-cohort tables include matching original/augmented D views and the requested baselines, with replayable metrics and support.
- Temporal availability and report identity rules prevent unacknowledged same-report leakage into features/selection or unsupported claims of new independent observations.
- Historical source ledgers show distinct-report observations and exclude the target report across original/augmented D, residual baselines and persistence; monthly copies do not inflate history counts or reset observation age.
- Per-fold report-id ledgers demonstrate separation between scoring reports and base/calibration-fitting sources for both branches, including OOF provenance; exclusions never change the frozen scoring keys.
- All copies retain their original source availability; fitting/calibration/history source dates respect the relevant cutoff independently of the copied target month and validity bounds.
- Added monthly training rows retain the normal per-row weights without report-length normalization; report-level count/weight summaries verify the intended greater influence of longer valid periods. Existing labels remain unchanged and area-month keys stay unique.
- Overlap decisions preserve existing raw labels, choose the latest original report month for blank cells, and leave unresolved equal-date label conflicts unfilled with replayable candidate/winner provenance.
- Original and augmented branches have equal declared search budgets and branch-specific fitting/calibration/selection ledgers, but identical outer evaluation keys/truth. D-selected is chosen before reading that fold's outer scores.
- Selection/calibration support counts distinct original-report months (latest three, minimum two); per-round copied rows remain fully weighted and all chronological/report exclusions remain verifiable.
- Every recipient was fully empty before augmentation and receives one source's entire six-field label; no partial original block or existing value is overwritten.
- Existing q3 model/selection/calibration behavior remains the baseline except for approved label-related changes; no execution before written spec/grill and subsequent authorization.
